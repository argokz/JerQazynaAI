## Окружение и возобновление

Отдельная `.venv-emit`: Python **3.12.3**, earthaccess **0.19.0**, h5netcdf **1.8.1**.
Все установленные зависимости зафиксированы в
[requirements/py312-emit.txt](../requirements/py312-emit.txt). Среда `.venv` Python 3.10
и её зависимости не обновлялись. Восстановление отдельной среды:

```powershell
C:/python312/python.exe -m venv .venv-emit
.venv-emit/Scripts/python.exe -m pip install -r requirements/py312-emit.txt
.venv-emit/Scripts/python.exe -m pip install --no-deps -e .
```

Пользователь выполняет вход в своём локальном терминале; секреты в чат не передаются:

```powershell
.venv-emit/Scripts/python.exe -c "import earthaccess; earthaccess.login(strategy='interactive', persist=True)"
```

Для Windows earthaccess сохраняет учётные данные в пользовательском `_netrc` либо пути
из переменной `NETRC`. Автоматическая команда `fetch` проверяет стратегии environment/netrc
без интерактивных запросов и без сохранения секретов в manifest. При отсутствии входа
возвращает код **2**. `prepare` требует готовый и проверенный научный комплект.

Продолжение на уже зафиксированном наборе:

```powershell
.venv-emit/Scripts/python.exe -m jerqazyna.cli emit fetch configs/pilots/emit_train_2026-10-20.yaml
.venv-emit/Scripts/python.exe -m jerqazyna.cli emit prepare configs/pilots/emit_train_2026-10-20.yaml
.venv-emit/Scripts/python.exe -m jerqazyna.cli emit report configs/pilots/emit_train_2026-10-20.yaml
```

Если вход выполнен только в браузере, его cookies не передаются Python. Для работы целиком
через боковую панель добавлена локальная форма ввода токена:

```powershell
.venv-emit/Scripts/python.exe -u -m jerqazyna.data.emit_login configs/pilots/emit_train_2026-10-20.yaml
```

Команда печатает одноразовый адрес на `127.0.0.1` со случайным путём. Пользователь сам
создаёт Bearer Token на официальной странице Earthdata, вставляет его в локальное поле
и нажимает кнопку продолжения. Форма не требует пароль и не отправляет секрет в чат.
Она проверяет Host/Origin и случайный путь, запрещает внешние ресурсы и кэширование.
Токен передаётся в окружение только дочернего процесса `fetch`, без записи на диск,
вывода дочерних ошибок или сохранения cookies браузера. Затем автоматически запускаются
`prepare` и `report`. Лимит и журнал загрузки те же; новые сцены не выбираются.
`login_handoff.json` содержит только стадию и PID, а статус страницы — число готовых
ассетов и расход байтов. При ошибке стадия фиксируется; скрытых автоматических повторов нет.

Поддержка токена опирается на [официальный пример NASA](https://urs.earthdata.nasa.gov/documentation/for_users/data_access/python_user_token_script).
Доступ подтверждён успешной загрузкой всех научных файлов 20.10.2026. Токен передан
локальному процессу без записи на диск или вывода в чат. Создание/отзыв токена в аккаунте
NASA выполняет пользователь. Готовый набор повторно используется офлайн без авторизации.

Новый `search` нужен только для намеренного обновления каталога/выборки. Он не удаляет
старый набор. Глобальный журнал `data/pilots/emit_transfer_ledger.json` сохраняется между
поисками и пилотами. Его нельзя обнулять для обхода лимита. Максимум — **10737418240 байт**.
`observed_bytes` считает байты, возвращённые чтением; `charged_bytes` резервируется до
чтения и является консервативным счётчиком лимита. При прерывании или неизвестной длине
последний резерв может превышать фактически полученный объём. Повторы и тела перенаправлений
также учитываются; скрытые HTTP-retry отключены. Метаданные CMR и вход в сервис авторизации
не являются загрузкой научных файлов.

Файл становится готовым после завершения передачи, проверки HDF5/NetCDF и записи SHA-256.
Повреждённый файл требует новой передачи с расходом того же бюджета. Полный проверенный
набор доступен офлайн. `.part` и неполные комплекты не считаются готовыми. Одновременную
загрузку блокирует lock с PID; после аварии перед удалением stale lock нужно проверить,
что соответствующий процесс завершён.

## Научная обработка

Реализация следует [примеру NASA по минералогии](https://nasa.github.io/LPDAAC-Data-Resources/external/Working_with_EMIT_L2B_Mineralogy.html)
для состава продуктов, GLT и no-match и [руководству NASA по качеству](https://nasa.github.io/LPDAAC-Data-Resources/external/How_to_use_EMIT_Quality_data.html)
для агрегированной маски. Научные файлы и их метаданные сохраняются как первоисточник.

- GLT трактуется как 1-based индексы; нули, fill, дробные и выходящие за массив индексы
  недопустимы. Проверяются размеры, порядок downtrack/crosstrack, CRS, geotransform,
  GLT и raw lat/lon всех трёх файлов. Сохраняются расстояния между центрами GLT и raw lat/lon.
- MIN содержит ID и глубину полос обеих групп; MINUNCERT — fit и неопределённость глубины.
  Исходные ID, таблица mineral_metadata, атрибуты и масштабы сохраняются. Scale/offset
  применяются один раз. Fit оставляется в распределяемых единицах с явным пояснением;
  дополнительное умножение или фильтрация по fit не выполняется.
- No-match `mineral_id=0` не приравнивается к fill: у него могут отсутствовать глубина и
  неопределённость. Нет наблюдения, fill/геолокация, aggregate QA, выработки и пригодность
  представлены отдельными кодами. Значения минералогии экспортируются отдельно от QA.
- Агрегированная QA-полоса определяется по имени, а не по жёсткому номеру; неизвестная
  схема или небинарный флаг останавливают обработку. Маска выработок строится из сохранённого
  источника полигонов с исходным буфером 3000 м; её хеш входит в протокол.
- Доли на 1 км — **приближение по равновеликой сетке 50 м**, 400 отсчётов на ячейку.
  Это не точное пересечение каждого 60-метрового пикселя с полигонами. Родные геопривязанные
  TIFF сохраняют данные на сетке GLT; доли на 1 км имеют явную численную дискретизацию.
  На границе AOI отдельно сохраняется `aoi_train_area_fraction`. Числители площади относятся
  к полной ячейке 1 км; в численном отчёте покрытие также нормируется на AOI∩train.
- Сцены одной даты сначала объединяются без двойного счёта перекрытий. Предпочитается
  пригодное наблюдение; равные случаи разрешаются по фиксированному порядку сцен.
  Число пригодных дат — число дат с ненулевой пригодной площадью в ячейке. No-match
  нормируется только на пригодную площадь; без пригодных пикселей его доля — NaN.
- Сохраняются квантили неопределённости/fit для совпадений, без порогов по меткам.
  Глубина полосы не переводится в содержание или запасы. Итоги вне train — NaN.

`report.json` и `report.md` содержат научное покрытие по сценам,
датам и участкам; `prepared_*/manifest.json` — хеши файлов, версии библиотек, геопривязку,
числа причин исключения и квантили. Исходный MINUNCERT остаётся доступным для проверки
трактовки fit; его значения не названы калиброванной вероятностью.

## Проверки и оставшаяся работа

Исходные **108 тестов прошли** до добавления новых проверок. Новые тесты покрывают
устаревшие хеши, неоднозначные соответствия, повторную правку, pending/rejected, сохранение
пустого статуса, запрет перемещения в закрытую ячейку, отсутствие авторизации, повторный
запуск, повреждение файлов, прерванную передачу и бюджет, перенаправления, GLT, QA,
маску выработок, no-match, объединение даты, изоляцию выходов и воспроизводимость.
Синтетические данные используются только внутри pytest, отдельно от реального пилота.
Итог: 34 новых теста прошли в Python 3.12; полная серия в Python 3.10 — 131 passed,
1 skipped, включая проверки реестра и транспорта. Научный модуль в среде baseline пропускается, поскольку
зависимости EMIT установлены отдельно. `ruff check src tests` — без ошибок.

Хеши **446 файлов** baseline и завершённых серий (75 + 176 + 195) сверены с сохранёнными
manifest; несовпадений нет. До и после научной обработки сохранены отдельные проверки:
`data/pilots/baseline_integrity_2026-10-20.json` и
`data/pilots/baseline_integrity_after_emit_2026-10-20.json`.
Источник меток, исходная baseline-таблица и train/test/buffer сохранены.

Реальные повторные `fetch`, `prepare` и `report` переиспользовали готовые файлы:
журнал передачи, указатели поколений и содержимое `report.json` не изменились.

Загрузка, реальная QA/неопределённость, проверка геопривязки и повторный расчёт ячеек
завершены. Квантили исходных fit и неопределённости сохранены по сценам и группам;
порогов по меткам нет. Проверка семи сцен не доказывает совместимость со всеми будущими
схемами файлов. Реестр сохраняет 23 конкретные неопределённости; это допустимый результат
проверки, а не подтверждение предлагаемых статусов или координат.

В двух AOI находятся **0 и 1 train-метка** соответственно (Kuru Tegerek в западном AOI).
Этого недостаточно для проверки прогностического вклада. Следующий шаг — оценить
представительность покрытия по меткам, странам, поясам и пространственным fold на train
и при необходимости заранее определить расширенный пилот с учётом остатка бюджета.
Следующий отдельный эксперимент описан в [ROADMAP](ROADMAP.md): сравнить baseline,
контроль наблюдаемости/QA и baseline + EMIT при одинаковых fold/фоновых seed/территории;
изменение меток оценивать отдельно. На этом этапе обучений нет и полезность EMIT для
прогноза не установлена.
