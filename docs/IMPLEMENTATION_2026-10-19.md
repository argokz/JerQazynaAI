# Первый этап реализации — 19 октября 2026 года

## Выполнено

- Строгая схема конфигурации: неизвестные поля/обработчики/параметры отклоняются,
  доли площади ограничены, CRS проверяется через pyproj, единицы должны быть метрами.
- Кэш сетки учитывает страны, CRS, шаг, хеши границ и версии геобиблиотек. Смена геометрии
  требует нового task_id, включая запуск с --force. Изменение границ при прежней
  геометрии пересчитывает маску и инвалидирует слои.
- Кэш слоёв проверяет SHA-256 входов и выходов, конфигурацию, код, библиотеки, список
  каналов и привязку. Частичные результаты не считаются готовыми. Обновление DEM
  отзывает готовность gravity, даже если выбран только DEM. Проверка --layers также
  отзывает готовность изменившихся невыбранных слоёв.
- Метаданные записываются через временный файл. Готовность слоя отзывается до начала
  пересчёта; авария не оставляет действующий маркер готовности.
- Отсутствующие обязательные метки не оставляют старый labels.csv. Для слоёв добавлен
  required; CLI возвращает ошибку при отсутствии обязательного входа.
- Зависимости pandas/pyogrio/openpyxl объявлены явно. Добавлен снимок версий Python 3.10
  в requirements/py310-geo.txt и отдельное геозадание CI. openpyxl установлен локально.
- estimate_capture рассчитывает ожидаемый захват для равных прогнозов и exact-интервал
  с консервативной огибающей неопределённости ties. Bootstrap сохранён с exact-огибающей.
  NaN, неверные индексы и несовместимые маски отклоняются. Интервал не учитывает
  пространственную зависимость; этот этап анализа ещё впереди.

## Повторение

Проверено в новом изолированном окружении Windows / Python 3.10 с установкой
через requirements/py310-geo.txt: **92 теста прошли**, ruff без ошибок.
Проверка зависимостей pip check также прошла. Проверка входов основной задачи успешна.
Повторная подготовка реального разбиения вернула то же поколение и подтвердила хеши.

```bash
pip install -c requirements/py310-geo.txt -e ".[geo,dev]"
pytest -q
ruff check src tests
jerqazyna validate-config configs/tasks/porphyry_cu_balkhash.yaml --check-inputs
jerqazyna prepare-labels configs/tasks/porphyry_cu_balkhash.yaml
jerqazyna prepare-split configs/tasks/porphyry_cu_balkhash.yaml
```

Старые тяжёлые растры не пересчитывались и автоматически не объявляются проверенными
новым механизмом кэша. Перед обучением требуется их подготовка с новыми отпечатками.
Проверка в CI на Ubuntu выполняется после публикации изменений; локальные результаты
проверок не являются результатами удалённого CI.
